---
title: "WebSocket streams"
description: "Real-time book, trades and order streams over one socket."
---

Connect to `wss://api.numofx.com/ws` and subscribe to any number of channels. Each stream sends a snapshot, then a delta for every state change, using JSON text frames.

| Channel | Access | Snapshot | Updates |
| --- | --- | --- | --- |
| `book` | Public | Same as `GET /book` | Price-level size changes |
| `trades` | Public | Same as `GET /trades` | One frame per fill |
| `orders` | Requires [auth](#authentication) | Your open orders | Your status and fill changes |

## Update delivery

- Updates are not batched or rate-limited. Each change is one frame with its own `seq`.
- A quiet market can go minutes without a frame. The server still pings every 15 seconds and drops connections that miss pongs.
- A fill's `trades`, `book` and `orders` deltas arrive as one contiguous block of `seq` values.

A gap in `seq` means you missed an event, so [resume](#resume-after-reconnect).

## Client frames

### Subscribe

```json
{ "op": "subscribe", "channel": "book", "market": "cNGN-USDC" }
```

<ParamField body="op" type="string" required>
  `subscribe`, `unsubscribe`, `auth` or `ping`.
</ParamField>

<ParamField body="channel" type="string">
  `book`, `trades` or `orders`.
</ParamField>

<ParamField body="market" type="string">
  A market such as `cNGN-USDC`, or `asset_address:sub_id`. Required for `book` and `trades`, optional for `orders`. The deprecated `USDCcNGN-SPOT` is accepted until 2027-01-06.
</ParamField>

<ParamField body="since_seq" type="integer">
  The last `seq` you processed. The server replays from there instead of sending a snapshot.
</ParamField>

Subscribing twice to the same channel and market does nothing.

### Unsubscribe

```json
{ "op": "unsubscribe", "channel": "book", "market": "cNGN-USDC" }
```

### Ping

```json
{ "op": "ping" }
```

The server replies with `{ "type": "pong" }`. Most clients can rely on protocol pings instead.

## Server frames

| `type` | Meaning |
| --- | --- |
| `snapshot` | Full state at `seq`. Sent first after subscribe. |
| `update` | One delta, after the snapshot's `seq`. |
| `ack` | Acknowledges `auth` or `unsubscribe`. |
| `pong` | Reply to `ping`. |
| `error` | Carries `code` and `message`. |

```json
{
  "type": "update",
  "channel": "book",
  "market": "cNGN-USDC",
  "seq": 10441,
  "data": { "…": "…" }
}
```

## Resume after reconnect

Track the highest `seq` you applied per channel and market, then subscribe with it:

```json
{ "op": "subscribe", "channel": "book", "market": "cNGN-USDC", "since_seq": 10441 }
```

The server replays what you missed. If `since_seq` is too old, you get `resume_too_old` and a fresh `snapshot`, so discard your local state and rebuild from it.

## Authentication

Required before subscribing to `orders`. Sign this exact message with `personal_sign`, using unix seconds and no trailing newline:

```text
<domain> wants you to authenticate for the Numo markets WebSocket.
Address: <address>
Nonce: <nonce>
Issued At: <issued_at>
Expiration Time: <expiry>
```

Then send:

```json
{
  "op": "auth",
  "address": "0xC7bE60b228b997c23094DdfdD71e22E2DE6C9310",
  "signature": "0x…",
  "nonce": "b3f1…",
  "issued_at": 1745000000,
  "expiry": 1745000300
}
```

Use a unique `nonce` per frame and a short validity window, because the server enforces a maximum. Success returns `{ "type": "ack", "message": "authenticated" }`, and the connection stays authorized until it closes. [Order history](/api-reference/endpoint/order-history) frames are not accepted here.

## Error codes

| Code | Cause |
| --- | --- |
| `bad_json` | Frame was not valid JSON. |
| `bad_op` | Unknown `op`. |
| `bad_channel` | Unknown channel. |
| `unknown_market` | Market did not resolve. |
| `auth_required` | Subscribed to `orders` without authenticating. |
| `auth_failed` | Signature, domain or expiry check failed. |
| `resume_too_old` | `since_seq` is too old. A fresh snapshot follows. |
| `stream_reset` | Subscription dropped. Resubscribe with `since_seq`. |
| `snapshot_failed` | Snapshot could not load. Resubscribe. |
| `slow_consumer` | Your client fell behind and was disconnected. Reconnect and resume. |
