---
title: 'Create a withdrawal'
openapi: 'POST /withdrawals'
---

Withdraws from a subaccount held by Matching with one signed `Action`. The venue pays the gas and sends the tokens to `owner`. The account stays in Matching, so trading continues.

## Signing the action

Sign an [`Action`](/signing) against the `Matching` domain:

| Field | Value |
| --- | --- |
| `subaccountId` | the subaccount, with you as its recorded owner |
| `nonce` | any unused `uint256`, per owner and module |
| `module` | `0x0a10AE2f5D2482cE1e43bC309D430B8861C2b5aB` |
| `data` | `abi.encode(address asset, uint256 amount)` |
| `expiry` | unix seconds, at most one hour ahead |
| `owner` | your address, which receives the tokens |
| `signer` | same as `owner` |

`asset` is the asset your balance is held in, not the token paid out:

| Balance | `asset` | Paid out as |
| --- | --- | --- |
| USDC | `0xA74E49b4Ed7cb176bc02ef4D8a1A3240C9aD4272` | USDC `0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913` |
| cNGN | `0x37c976bb5d4887a714ef19AF6B83e34fe2f37c98` | cNGN `0x46C85152bFe9f96829aA94755D9f915F9B10EF5F` |

Accounts opened before 2026-10-04 can also withdraw the retired wrapped USDC `0x364058aFF6f36E01505fB2Cc870f8B6BD4835e84` and wrapped cNGN `0x9D806fD040a719D27a8E5E77dc5aE0ED1e089493`.

`amount` uses the token's 6 decimals: 1 USDC is `1000000`.

Send the fields as strings, with `data` as hex:

```json
{
  "action": {
    "subaccount_id": "19",
    "nonce": "7328734720000000",
    "module": "0x0a10AE2f5D2482cE1e43bC309D430B8861C2b5aB",
    "data": "0x000000000000000000000000a74e49b4ed7cb176bc02ef4d8a1a3240c9ad427200000000000000000000000000000000000000000000000000000000001e82d7",
    "expiry": "1789400600",
    "owner": "0xYourAddress",
    "signer": "0xYourAddress"
  },
  "signature": "0x…"
}
```

## Errors

| Status | Meaning |
| --- | --- |
| `400` | Invalid request, Matching does not hold the subaccount, or the issuer froze your wallet. |
| `401` | The signature does not authorize the action. |
| `403` | Matching does not record `owner` as the subaccount's owner. |
| `422` | The simulation reverted. `revert` names it, such as `WERC_CannotBeNegative` for more than the account holds. |
| `429` | One withdrawal in progress per owner, five a minute. |
| `502` | Outcome unknown. See the warning below. |
| `503` | Withdrawals are off, a read failed, or the issuer paused the token or froze the custody contract. |

## The outcome

A **200** carries `accepted`, `tx_hash`, `receipt_status` and `block_number`. `receipt_status: "timeout"` means broadcast but not yet confirmed, so watch the hash.

<Warning>
  After a **502**, check your balance before signing another withdrawal: a second signed withdrawal is a second withdrawal. Resending the **same** signed request is safe.
</Warning>
